# Architecture

Nasolt Vault is a local Windows desktop application. `src/nasolt_vault/` is the importable package; `python -m nasolt_vault` is its source entry point. Its `main.py` owns the CustomTkinter event loop, vault session, tray lifecycle, and startup routing. The `ui/` package renders the login, vault, settings, import/export, quick access, and Lockout Lab views. `quick_access.py` brokers Vault Summon authentication; `windows_shortcuts.py`, `windows_startup.py`, `windows_tray.py`, and `windows_hello.py` call Windows facilities. Background workers return results to Tk rather than updating widgets directly.

`paths.py` selects the data folder. `NASOLT_DATA_DIR` overrides it for isolated tests. In a source checkout, the historical repository-root `data/vault.enc` remains authoritative despite the package move into `src/`; installed mode otherwise uses `%APPDATA%\Nasolt Vault\data`. No user data moves automatically. Never test against a real user data folder.

`vault.py` coordinates one unlocked session and an OS file lock. `crypto.py` implements the existing NSLT v1 envelope: Argon2id derived key and AES-256-GCM authenticated encryption. Saves use a unique temporary file and preserve a prior encrypted backup. `export.py` handles password-protected `.nve` exports and warned plaintext CSV/JSON formats. `lockout_lab.py` stores an optional encrypted sidecar derived from an unlocked vault session; its simulations use dependency metadata, not passwords. `hello_enrollment.py` stores authenticated preference metadata, not the master password or vault key. Windows Hello is session reauthentication only.

`packaging/windows/` contains NSIS installer source, build scripts, and ignored `artifacts/` output. `packaging/linux/` and `packaging/macos/` contain documentation only. `tests/` uses disposable synthetic vaults and contains the double-click test launcher. `.github/workflows/` contains the Windows source test job. The root `.gitignore` remains as a security-critical exception to the six-folder layout so legacy root `data/` and generated files cannot be staged accidentally. See [Threat model](THREAT_MODEL.md), [Release checklist](RELEASE_CHECKLIST.md), and [Windows packaging](../packaging/windows/README.md).
