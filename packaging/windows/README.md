# Windows packaging source

The NSIS source, installation marker, and double-click build scripts live here. Python 3.12, pinned `packaging/requirements.txt`, pinned `packaging/requirements-build.txt`, and an independently installed NSIS compiler are required. Build output is local and ignored under `packaging/windows/artifacts/`.

From the repository root, run `packaging\windows\BUILD_WINDOWS.bat` to make the one-file app, then `packaging\windows\BUILD_INSTALLER.bat` to rebuild it and compile NSIS. The installer script does not download NSIS or upload any artifact. `packaging\windows\build.py` remains available for an already prepared Python environment. An NSIS compile alone does **not** approve the installer for distribution.

Current installer source uses version `2.0.0` and local name `Nasolt_Vault_Setup_2.0.0.exe`. For an approved binary release, calculate each artifact's checksum with `Get-FileHash -Algorithm SHA256 -LiteralPath '<artifact path>'` in PowerShell and publish its exact SHA-256 only after completing [the desktop checklist](../../docs/RELEASE_CHECKLIST.md). The local executable build, bundled self-test and NSIS compilation passed; real installation and upgrade checks remain unverified. See [Windows release-candidate verification](../../docs/WINDOWS_INSTALLER_VERIFICATION.md). Do not distribute either binary yet.

The NSIS source calls `--installer-shortcuts` for ownership checks before changing program files or deleting shortcuts. Its `--installer-upgrade` helper stages and hashes program files, retains verified previous copies until registration is complete, and uses a recovery journal for an interrupted upgrade. Vault data and sidecars are outside that transaction. Synthetic tests cover the helper and Windows Shell links. **Compilation and simulated failures do not verify real installation, upgrade, or uninstall behavior**; complete the disposable Windows checklist before any binary release.
