# Windows packaging source

The NSIS source and installation marker live here. The root `BUILD_WINDOWS.bat` and `BUILD_INSTALLER.bat` remain the supported double-click entry points; actual scripts live in `scripts/`. Python 3.12, pinned `requirements.txt`, pinned `requirements-build.txt`, and an independently installed NSIS compiler are required. Build output is local and ignored under `artifacts/windows/dist/`, `artifacts/windows/build/`, `artifacts/windows/spec/`, and `artifacts/windows/installer/`.

From the repository root, run `BUILD_WINDOWS.bat` to make the one-file app, then `BUILD_INSTALLER.bat` to rebuild it and compile NSIS. The installer script does not download NSIS or upload any artifact. `build.py` remains available for an already prepared Python environment. An NSIS compile alone does **not** approve the installer for distribution.

Current installer source uses version `2.0.0` and local name `Nasolt_Vault_Setup_2.0.0.exe`; do not change product versions as part of structural work. For an approved binary release, calculate each artifact's checksum with `Get-FileHash -Algorithm SHA256 -LiteralPath '<artifact path>'` in PowerShell and publish its exact SHA-256 only after completing [the desktop checklist](../../docs/RELEASE_CHECKLIST.md). A local executable build, bundled self-test, and synthetic GUI restart passed; the full executable checklist and NSIS installer remain unverified for distribution. Do not distribute either binary.

The NSIS source now calls the application's headless `--installer-shortcuts` helper before it writes program files or removes shortcuts. The helper checks shortcut target, arguments, working directory, icon, and hotkey against the selected installation, and requires the previous per-user install marker and registration before treating an existing fixed-name link as an upgrade. It preserves unrelated links and nonempty Start Menu folders, and stops when ownership is ambiguous. Synthetic unit and Windows Shell-link tests cover these rules. **The NSIS source has not been compiled or exercised as an installer**, so install, upgrade, and uninstall behavior still require the disposable Windows checklist before any binary release.
